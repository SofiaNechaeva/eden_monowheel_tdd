# Моноколесо Эдем

Учебная программная модель наземного транспорта по `SPEC.md` версии 1.0. Класс `EdenMonowheel` моделирует движение по направляющей борозде, грунту и песку, зарядку, пассажирскую гондолу, помощника и уборочную машину.

## Установка и проверка

Рекомендуется Python 3.12: эта версия используется в GitHub Actions и при проверке реализации. Сторонние библиотеки не нужны; тесты используют стандартный `unittest`.

Из корня репозитория:

```bash
python -m unittest discover -s tests -v
```

В Windows вместо `python` можно использовать `py -3.12`:

```powershell
py -3.12 -m unittest discover -s tests -v
```

Проверены 75 тестов автора: 72 модульных и 3 сценарных, все проходят. Основа проверки — исходные артефакты коммита `ca03c63b821a140d9f1044ed77e91a7b46ee8c99`. ТЗ и тесты при реализации не изменялись.

## Состав проекта

- `eden_monowheel.py` — класс транспорта и доменные исключения.
- `SPEC.md` — требования автора.
- `TEST_CASES.md` — таблица тест-кейсов.
- `tests/test_unit.py` — модульные тесты.
- `tests/test_scenarios.py`, `tests/pilot.py` — сценарии и обёртка-пилот.
- `reflection.md` — рефлексия разработчика.

Модуль представляет программный интерфейс, отдельного интерактивного меню нет. Запуск `python eden_monowheel.py` ничего не выводит: класс нужно импортировать.

## Пример использования

Сохраните пример в `demo.py` рядом с модулем и выполните `python demo.py`:

```python
from eden_monowheel import EdenMonowheel

wheel = EdenMonowheel("Эдем", 4, 300, 80)
wheel.move(100, 0.1, "track", main_track=True)
wheel.attach_equipment()
wheel.assess_trench(1)
wheel.set_equipment_active(True)
wheel.move(20, 0.05, "ground", arrive_on_track=True)
print(wheel.position_km, wheel.mileage_km, wheel.energy)
print(wheel.trench_filled, wheel.on_track)
wheel.recharge(100)
print(wheel.energy)
```

Ожидаемый вывод:

```text
10.0 11.0 63.0
True True
100.0
```

## Публичные методы

| Метод | Назначение и результат |
| --- | --- |
| `EdenMonowheel(name, wheel_diameter_m, max_speed_kmh, energy=100.0)` | Создать транспорт с нулевым пробегом |
| `move(speed_kmh, time_h, terrain, main_track=False, arrive_on_track=False)` | Выполнить проход, вернуть пройденное расстояние в км |
| `calculate_energy(speed_kmh, time_h, terrain)` | Вернуть расход только на движение, не изменяя состояние |
| `can_overcome(obstacle_width_m)` | Вернуть, не превышает ли ширина половину диаметра колеса |
| `recharge(target_energy)` | Зарядить до заданного уровня на борозде |
| `open_gondola()`, `close_gondola()` | Открыть или закрыть гондолу |
| `attach_equipment()`, `detach_equipment()` | Подключить или отсоединить уборочную машину |
| `set_equipment_active(active)` | Включить или выключить уборочную машину |
| `assess_trench(volume_t)` | Задать новую оценку рва в тоннах |
| `set_helper_active(active)` | Включить или выключить помощника |
| `get_status()` | Вернуть независимый словарь состояния с 14 ключами |

Управляющие методы без отдельно указанного результата возвращают `None`.

## Правила модели

- Борозда (`track`) не расходует аккумулятор. Грунт (`ground`) расходует 2 единицы на км, песок (`sand`) — 4.
- На грунте предел скорости 40 км/ч, с помощником — 50; на песке — 20. Конструктивный предел действует всегда, в том числе при движении назад.
- `position_km` учитывает только основную борозду и направление. `mileage_km` учитывает весь пройденный путь.
- `main_track=True` допустим только на борозде. `arrive_on_track=True` допустим только на грунте и песке и разрешает зарядку после прибытия.
- Нулевая скорость после проверки параметров возвращает `0.0` без изменения состояния, даже при открытой гондоле.
- Уборочная машина за ненулевой проход по грунту или песку перемещает до 1 тонны и тратит 15 единиц на тонну. Расход входит в общую проверку достаточности энергии до начала прохода.
- Все публичные атрибуты доступны только для чтения, кроме `on_track`: ему можно присвоить строго `bool` для подготовки сценария.
- Числовые параметры принимают конечные `int` и `float`, но не `bool`. Состояние хранит числовые величины как `float`.

## Ошибки

Некорректные аргументы вызывают `ValueError`. Присваивание атрибуту только для чтения вызывает `AttributeError`.

Доменные исключения наследуются от `MonowheelError`:

- `MonowheelGondolaOpen` — движение при открытой гондоле.
- `MonowheelNoEnergy` — недостаток энергии на весь проход.
- `MonowheelNotOnTrack` — зарядка вне борозды.
- `MonowheelEquipmentError` — повторное подключение, отключение отсутствующего оборудования или включение неподключённого.

Порядок проверок движения: аргументы и результаты расчёта → гондола → энергия. Ошибка не оставляет частично изменённого состояния.

Вопросы раздела 9 SPEC реализованы согласно действующим правилам: зарядка при открытой гондоле разрешена; подключение оборудования не зависит от места и заряда; оценка рва заменяется; ров не блокирует маршрут; помощник доступен при нулевой энергии. Дополнительные ограничения не вводились.
